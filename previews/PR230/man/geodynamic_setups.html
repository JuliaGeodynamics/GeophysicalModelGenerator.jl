Numerical model setups ​

In order to generate numerical simulations from setups created with GeophysicalModelGenerator.jl, we provide a few routines that directly create setups.

The routines provided here have the following functionality:

  • Add lithospheric boxes to a setup, that may have a layered structure and various thermal structures

  • Add various geometries (spheres, cuylinders, ellipsoids)

  • Add lithospheric structure

  • Add various 1D thermal structures (and possibilities to combine them)

Map-view outlines of plates, weak zones, faults and trenches can be drawn in any vector graphics program, such as Inkscape, Affinity or Illustrator, exported as SVG and read with read_outlines, which returns them in drawing order: closed ones as polygons for add_plate!, open ones as Trace of add_fault! and Trench. Name each shape (or its layer) after the outline it represents, and draw a reference line whose end points have known model coordinates, or let the page span the model domain. write_outlines stores outlines as a CSV file.

Layers with curved or perturbed interfaces, listric faults, faults with a curved trace and Gaussian thermal anomalies are shown in the tutorial Curved layers, curved faults and thermal anomalies.

GeophysicalModelGenerator.add_box! Function
julia
add_box!(Phase, Temp, Grid::AbstractGeneralGrid; xlim::Tuple = (20,100), [ylim::Tuple = (1,10)], zlim::Tuple = (10,80),
        Origin=nothing, StrikeAngle=0, DipAngle=0,
        phase = ConstantPhase(1),
        T=nothing,
        segments=nothing,
        cell=false )

Adds a box with phase & temperature structure to a 3D model setup. This simplifies creating model geometries in geodynamic models

Parameters

  • Phase - Phase array (consistent with Grid)

  • Temp - Temperature array (consistent with Grid)

  • Grid - grid structure (can be any of the grid types in GMG)

  • xlim - left/right coordinates of box

  • ylim - front/back coordinates of box [optional; if not specified we use the whole box]

  • zlim - bottom/top coordinates of box

  • Origin - the origin, used to rotate the box around. Default is the left-front-top corner. Depths of the phase and temperature structures are measured from the top of the box, wherever Origin lies

  • StrikeAngle - strike angle of slab

  • DipAngle - dip angle of slab

  • phase - specifies the phase of the box. See ConstantPhase(),LithosphericPhases(); nothing keeps the phases

  • T - specifies the temperature of the box. See ConstantTemp(),LinearTemp(),HalfspaceCoolingTemp(),SpreadingRateTemp(),LithosphericTemp()

  • segments - optional parameter to define multiple ridge segments within the box, for T = SpreadingRateTemp()

  • cell - if true, Phase and Temp are defined on centers

Examples

julia
julia> Grid = read_LaMEM_inputfile("test_files/SaltModels.dat")

  nel         : (32, 32, 32)
  marker/cell : (3, 3, 3)
  markers     : (96, 96, 96)
  x           ϵ [-3.0 : 3.0]
  y           ϵ [-2.0 : 2.0]
  z           ϵ [-2.0 : 0.0]
julia> Phases = zeros(Int32,   size(Grid.X));
julia> Temp   = zeros(Float64, size(Grid.X));
julia> add_box!(Phases,Temp,Grid, xlim=(0,500), zlim=(-50,0), phase=ConstantPhase(3), DipAngle=10, T=ConstantTemp(1000))
julia> Model3D = ParaviewData(Grid, (Phases=Phases,Temp=Temp)); # Create Cartesian model

GeophysicalModelGenerator.add_layer! Function
julia
add_layer!(Phase, Temp, Grid::AbstractGeneralGrid; xlim::Tuple = (1,100), [ylim::Tuple = (0,20)], zlim::Tuple = (0,-100),
        phase = ConstantPhase(1),
        T=nothing, cell=false )

Adds a layer with phase & temperature structure to a 3D model setup. The most common use would be to add a lithospheric layer to a model setup. This simplifies creating model geometries in geodynamic models

Parameters

  • Phase - Phase array (consistent with Grid)

  • Temp - Temperature array (consistent with Grid)

  • Grid - grid structure (usually obtained with read_LaMEM_inputfile, but can also be other grid types)

  • xlim - left/right coordinates of box

  • ylim - front/back coordinates of box

  • zlim - bottom/top coordinates of box. Each bound is either a number, a function z(x, y), or a surface CartData (e.g. imported topography or a Moho map), which gives a layer with a curved or perturbed bottom or top surface. A surface must cover xlim and ylim.

  • phase - specifies the phase of the box. See ConstantPhase(),LithosphericPhases(); nothing keeps the phases

  • T - specifies the temperature of the box. See ConstantTemp(),LinearTemp(),HalfspaceCoolingTemp(),SpreadingRateTemp()

Numeric limits may be given in either order. Thermal and phase structures see the vertical coordinate z - top(x, y), the (negative) depth below the top of the layer, so that the layers of LithosphericPhases and the profile of HalfspaceCoolingTemp start at the top of the layer, whether it is a number or a curved surface. LinearTemp goes from Ttop at the top to Tbot at the bottom of the layer at every (x, y).

GeophysicalModelGenerator.add_fault! Function
julia
add_fault!(Phase, Temp, Grid::AbstractGeneralGrid;
    Start=(20,100), End=(10,80),
    Trace=nothing,
    Fault_thickness=10.0,
    Depth_extent=nothing,
    DipAngle=0e0,
    DetachmentDepth=nothing,
    phase=ConstantPhase(1),
    T=nothing,
    cell=false)

Adds a fault to the given 3D grid by modifying the Phase and Temp arrays. For a 2D grid, use add_box instead. Depths in phase and T are measured below the top of the fault's Depth_extent.

Arguments

  • Phase: Phase array

  • Temp: Temp array

  • Grid: The grid on which the fault is to be added.

  • Start: Tuple representing the starting coordinates of the fault (X, Y).

  • End: Tuple representing the ending coordinates of the fault (X, Y).

  • Trace: If not nothing, the surface trace of the fault as a polyline of two or more points (X, Y), which replaces Start and End. The fault follows the curved trace, and its dip is perpendicular to it.

  • Fault_thickness: Thickness of the fault.

  • Depth_extent: Depth extent of the fault. If nothing, the fault extends through the entire domain.

  • DipAngle: Dip angle of the fault, measured from the vertical. A positive angle dips to the right of the direction from Start to End (or along Trace).

  • DetachmentDepth: If nothing, the fault is planar. Otherwise, the fault is listric: it starts with DipAngle at z = 0 and flattens with depth into a horizontal detachment at z = -DetachmentDepth, following z = -DetachmentDepth * (1 - exp(-h / (DetachmentDepth * tand(DipAngle)))) at a horizontal distance h from the trace. The thickness is accurate where the curvature radius exceeds Fault_thickness.

  • phase: Phase to be assigned to the fault; nothing keeps the phases

  • T: Temperature to be assigned to the fault. If nothing, the temperature is not modified.

Example

julia
add_fault!(Phase, Temp, Grid;
        Start=(20,100), End=(10,80),
        Fault_thickness=10.0,
        Depth_extent=(-25.0, 0.0),
        DipAngle=-10.0,
        phase=ConstantPhase(1)
        )

Listric normal fault that flattens into a detachment at 15 km depth:

julia
add_fault!(Phase, Temp, Grid;
        Start=(50,0), End=(50,100),
        Fault_thickness=2.0,
        DipAngle=30.0,
        DetachmentDepth=15.0,
        phase=ConstantPhase(1)
        )

Fault with a curved surface trace, dipping towards the center of the arc:

julia

GaussianTemp(Amplitude=200, Width=50)

Adds a Gaussian temperature anomaly to the current temperature (e.g. a geotherm set before), centered in the region it is added to (e.g. the center of a sphere or box), as for a plume head or a thermal seed:

T = T + Amplitude * exp(-((x - x0)² / Wx² + (y - y0)² / Wy² + (z - z0)² / Wz²) / 2)

GeophysicalModelGenerator.Trench Type
julia
Trench structure

Structure that defines the geometry of the trench and the slab.

Parameters

  • Start - Start of the trench (x,y) coordinates

  • End - End of the trench (x,y) coordinates

  • Trace - If not nothing, the trench as a polyline of two or more (x,y) points, which replaces Start and End; see bezier_curve for smooth curves. The slab bends perpendicular to the curved trench, to its left for direction = 1 and to its right for direction = -1, and ends at the ends of the trench.

  • n_seg - The number of segment through which the slab is discretize along the dip

  • Length - The length of the slab

  • Thickness - The thickness of the slab

  • Lb - Critical distance through which apply the bending angle functions Lb ∈ [0,Length];

  • θ_max - maximum angle of bending ∈ [0°,90°].

  • direction - the direction of the dip The rotation of the coordinate system is done as such that the new X is parallel to the segment. Since the rotation is anticlockwise the coordinate y has specific values: direction tells if the subduction is directed along the positive or negative direction of the new y coordinate system. In practice, it apply an additional transformation to y by multiplying it with -1 or +1;

  • d_decoupling - depth at which the slab is fully submerged into the mantle. A LinearWeightedTemperature of the slab with dir = :X blends its two structures over the length along the slab down to this depth; with another dir, its crit_dist is kept.

  • type_bending - is the type of bending angle of the slab [:Linear, :Ribe]. The angle of slab changes as a function of l (∈ [0,Length]). l is the actual distance along the slab length from the trench. In case: - :Linear math θ(l) = ((θ_max - 0.0)/(Lb-0))*l; - :Ribe math θ(l) = θ_max*l^2*((3*Lb-2*l))/(Lb^3); which is taken from Ribe 2010 [Bending mechanics and mode selection in free subduction: a thin-sheet analysis] For l>Lb, θ(l) = θ_max;

  • WeakzoneThickness - Thickness of the weakzone [km]

  • WeakzonePhase - Phase of the weakzone

  • Bending - If not nothing, the dip profile as (angle, length) pairs, e.g. [(20, 150), (80, 250)]: starting at 0° where the slab starts, the dip changes linearly to each angle (in degrees) over each length (in km) along the top of the slab. It replaces Length, Lb, θ_max and type_bending.

  • Behind - Length [km] of the slab behind the trench, where the slab starts, e.g. to bend the plate before the trench.

  • ThermalThickness - If not nothing, the thickness [km] below the top of the slab within which add_slab! sets the temperature, with the phases set within Thickness; e.g. to reach the mantle temperature at the base of the thermal structure of the slab.

  • Tear - If not nothing, a Tear that thins the slab towards a slab break-off. Start and Tip of the tear are distances along the trench from Start of the trench (along Trace for a curved trench), or map points. ThermalThickness thins by the same factor as Thickness, and the weak zone thins by it with its base on the slab surface, so that both vanish where the slab is torn.

GeophysicalModelGenerator.Tear Type
julia
Tear(; Depth, Width, Start, Tip)

Tear of a slab towards a slab break-off, for the Tear of a BezierSlab or a Trench. The slab necks around the depth Depth [km, positive downwards]: the neck starts at Start along the trench, where the slab has its full thickness, and deepens towards Tip, where the slab is torn through at Depth; beyond Tip the torn gap widens, with a detached slab below it. Width [km] is the vertical width of the neck. The tear runs in either direction along the trench.

Start and Tip are each a distance [km] along the trench (see BezierSlab and Trench), or a map point (x, y) whose nearest point on the trench in map view sets that distance; a map point beyond the ends of the trench is an error.

At a point of the slab surface at distance a along the trench and depth z, the slab thickness is multiplied by

julia
φ = clamp(1 - A exp(-((z - Depth) / Width)²), 0, 1),   A = max(0, (a - Start) / (Tip - Start))

The thickness is thus continuous and full before Start; beyond Tip (A > 1) the slab is torn over the depth interval |z - Depth| ≤ Width √(log A). Thermal and phase structures see the distance below the surface stretched by 1 / φ, so that crust and thermal boundary layer thin with the slab. The temperature is then blended with the temperature T₀ before the slab is added, T₀ + φ (T_slab - T₀), so that the neck warms as it thins, and the torn gap keeps T₀.

Example

julia
julia> tear = Tear(; Depth = 180, Width = 50, Start = 550, Tip = 770);
julia> add_slab!(Phases, Temp, Grid, BezierSlab(; Points, Thickness = 80, Tear = tear); phase = ConstantPhase(1))

GeophysicalModelGenerator.BezierSlab Type
julia
BezierSlab(; Points, Thickness = 100.0, Tear = nothing)

Slab whose top is a tensor-product Bézier surface, for add_slab!. Points[i, j] = (x, y, z) are the control points: i runs along the trench and j down the dip, such that the slab dips to the right of the trench seen in the direction of increasing i. The sections Points[i, :] may differ along the trench, and a slab whose sections start horizontally joins smoothly to a plate added with add_plate! along bezier_curve(Points[:, 1]).

The slab extends Thickness below the surface, measured perpendicular to it, so the surface must bend with radii larger than Thickness. Thickness is a number or a function (x, y, z) -> thickness of the point of the surface, e.g. to thin the slab towards a slab break-off, where the thickness reaches 0. Where a function thins the slab, it is compressed: thermal and phase structures see the distance below the surface stretched to the largest thickness, so that crust and thermal boundary layer thin with the slab and the temperature stays continuous.

Tear is nothing or a Tear, which thins the slab towards a slab break-off; it multiplies Thickness, also if that is a function. The distances Start and Tip of the tear are measured in map view along the edge bezier_curve(Points[:, 1]) of the surface, the trench, from its first point; a point of the surface is as far along the trench as the point of the edge with the same parameter along the trench.

Thermal and phase structures see the slab in its own coordinates: x is an estimate of the distance along the dip (from the mean length of the control polygons in j), which McKenzie_subducting_slab uses; y is the depth of the surface above the point; and z is the distance below the surface. A LinearWeightedTemperature with dir = :Y thus blends two thermal structures with the depth of the slab surface, e.g. from half-space cooling at the trench to McKenzie_subducting_slab at the base of the overriding plate.

Example

A trench that bends in map view, with sections that steepen along it:

julia
julia> trench = [(300.0, 0.0), (300.0, 400.0), (600.0, 600.0), (600.0, 1000.0)];   # control points along the trench
julia> section(dip) = [(0.0, 0.0), (120.0, 0.0), (220.0, -60.0), (220 + 250cosd(dip), -60 - 250sind(dip))];   # (distance, depth)
julia> dips = (30, 40, 50, 60);
julia> Points = [(trench[i][1] + section(dips[i])[j][1], trench[i][2], section(dips[i])[j][2]) for i in 1:4, j in 1:4];
julia> Grid = CartData(xyz_grid(0:20:1000, 0:20:1000, -400:20:0));
julia> Phases = zeros(Int32, size(Grid));
julia> Temp = zeros(Float64, size(Grid));
julia> add_slab!(Phases, Temp, Grid, BezierSlab(; Points, Thickness = 80.0); phase = ConstantPhase(1))

GeophysicalModelGenerator.compute_thermal_structure Function
julia
compute_thermal_structure(Temp, X, Y, Z, Phase, s::SpreadingRateTemp, segments)

Calculates the temperature distribution across the plate considering multiple ridge segments.

This function computes the thermal structure based on the perpendicular distance from each point to its corresponding ridge segment, and applies a thermal model using a spreading velocity and thermal age.

Parameters

  • Temp : Temperature field to be updated (array)

  • X, Y, Z : Coordinates of the points (arrays)

  • Phase : Phase of the material (unused)

  • s : SpreadingRateTemp object containing the thermal and spreading parameters

  • segments : List of ridge segments, where each segment is defined by two tuples representing the start and end coordinates (x1, y1) and (x2, y2) for each segment.

Note

The temperature at each point is calculated using the thermal age, which is determined by the spreading velocity and the distance from the point to the ridge segment that produced it. Consecutive segments are joined by transform faults, from the end of one segment to the start of the next; the fracture zones continue the transform faults as straight lines and separate the regions of the segments. The segments are therefore ordered along the ridge, and each pair of consecutive segments must lie on opposite sides of their transform fault.

The function works with one or more segments, and the ridge can be placed at any position within the box, not only at its boundary.

The thermal age is capped at maxAge years, and the temperature is adjusted based on the distance to the ridge and the corresponding thermal gradient.

GeophysicalModelGenerator.read_outlines Function
julia
outlines = read_outlines(filename; tolerance = 1.0, bounds = nothing, reference = nothing)

Reads named map-view outlines, such as plate boundaries, weak zones and trenches, from a file. Returns a vector of named tuples (; name, closed, x, y) in the order of the file, which is the drawing order of an SVG file, so that later outlines can be painted over earlier ones. A closed outline is a polygon, e.g. for add_plate!(Phase, Temp, Grid; xlim = o.x, ylim = o.y, ...); only an open outline is valid as Trace of add_fault! or of a Trench, which also reject traces that turn by more than 90° between consecutive segments.

The format follows from the extension of filename:

  • .csv: one row per vertex with the columns id,name,closed,x,y, as written by write_outlines; the rows of an outline share its id, and closed is 0 or 1. Lines starting with # are comments.

  • .svg: every visible shape (path, rect, circle, ellipse, line, polyline, polygon) outside defs, clip paths, masks, patterns, symbols and markers is an outline, so that drawings from any vector graphics program (Inkscape, Affinity, Illustrator, ...) can be read. Elements hidden by display: none, such as hidden Inkscape layers, give no outlines, though they may hold the reference shape, and shapes exported as images, e.g. because they are semi-transparent, are not read. An outline is named by its attribute label (geomIO, or Inkscape's inkscape:label) or data-name (Illustrator), else by the label of its closest labeled group or Inkscape layer (or the layer's id), else by its own id, else by the id of its closest group (the layer name in Affinity). A <use> with a label names its copy. A path with several subpaths, e.g. a polygon with holes, gives one outline of the same name per subpath. A subpath that ends at its start is closed. Curves and arcs are flattened into polylines that deviate less than tolerance from them, in model units. Drawing coordinates are mapped to model coordinates by one of

    • reference = name => ((X0, Y0), (X1, Y1)): the shape name, typically a straight line, starts at the model coordinates (X0, Y0) and ends at (X1, Y1);

    • bounds = (xmin, xmax, ymin, ymax): the model coordinates of the viewBox of the drawing (its page);

    • a shape with an attribute CoordRef = "X0,Y0 X1,Y1", as in geomIO, used if neither keyword is given.

    The reference shape is not returned as an outline and must span a nonzero extent in x and y. Lengths with units (e.g. width="10mm" of a rect), arc flags written without a separator before the next number (a 5 5 0 0110 0) and <use> of a <symbol> with a viewBox are not supported and throw an error.

Example

julia
julia> outlines = read_outlines("MapviewSetup.svg"; tolerance = 4.0);
julia> adria = only(filter(o -> o.name == "Adria", outlines));
julia> add_plate!(Phases, Temp, Grid; xlim = adria.x, ylim = adria.y, zlim = (-110, 0), phase = LithosphericPhases(Layers = [30, 80], Phases = [10, 3, 1]))
